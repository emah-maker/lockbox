# FRAIM Skill: agent-llm-routing-config

## Skill Input
- `agent` - the CLI agent or app being routed (`claude-code`, `codex`, `gemini-cli`, `aider`, an Anthropic-SDK app, a custom agent). New agents are handled by the research step; no hardcoded list.
- `agent_version` - output of `<agent> --version`, used to scope research to the installed version.
- `cloud` - destination cloud (`aws`, `gcp`, `azure`, or other).
- `provider_target` - the LLM provider on that cloud (`bedrock`, `vertex`, `azure-openai`, etc.).
- `secret_path` - filesystem location of the bearer token / service account / API key. MUST be outside any git-tracked directory.
- `mechanism_override` - optional. One of `profile`, `env-var-script`, `config-patch`. Skips research and forces that mechanism; use only when the user has a strong reason.

## Skill Output
A working routing configuration that lets the user invoke the agent through the chosen cloud-hosted LLM, plus a short doc stating which mechanism was chosen, why, and how to invoke and revert. The shape matches the agent's *current canonical mechanism*, not a hardcoded preference:
- **Named profile** in the agent's current profile layout, invoked with `<agent> --profile <name>`.
- **Per-shell flip script** (`use-<cloud>-<provider>.<sh|ps1>`) under `$HOME/.cloud-llm-flip/` that the user dot-sources.
- **Config patch** (e.g., an `~/.claude/settings.json` `env` block) the user opts into.
