# FRAIM Skill: gtm-stack-configuration

## Skill Input
- Bowtie journey map: stage names, entry/exit criteria, and handoff definitions from `customer-journey-mapping` skill output or equivalent artifact.
- ICP profile list: 1–3 ICP clusters with firmographic attributes and buyer titles.
- Current tooling inventory (optional): list of tools the company currently uses across CRM, sequencing, analytics, and enrichment.
- Stack configuration scope: one or more of `crm-pipeline`, `sequences`, `lead-scoring`, `instrumentation`.
- Existing CRM configuration (optional): current pipeline stage names, field definitions, and scoring model.

## Skill Output
- **CRM pipeline configuration spec** (scope: `crm-pipeline`): pipeline stage names aligned to Bowtie left-bow stages (Educate through Sign), with entry/exit field requirements per stage and a field-level change plan listing: field name, current value (if known), proposed value, and reason.
- **Sequence platform configuration spec** (scope: `sequences`): recommended sequence cadences per ICP mapped to the outreach playbook, including sequence names, enrollment triggers, and unenrollment conditions.
- **Lead scoring model spec** (scope: `lead-scoring`): a two-component scoring model — fit score (firmographic/ICP match, 0–100) and behavior score (product and engagement signals, 0–100) — with scoring criteria, threshold definitions (MQL, SAL, SQL), and recommended review cadence.
- **Instrumentation event spec** (scope: `instrumentation`): event definitions for all 8 Bowtie stage transitions (Educate→Engage, Engage→Validate, Validate→Sign, Sign→Onboard, Onboard→Adopt, Adopt→Expand, Expand→Renew, Renew→Advocate). Each event: event name (snake_case), fire condition, required properties (with data type), and the Bowtie stage transition it maps to.
- **Quarterly maintenance checklist**: tasks to run every quarter to keep the stack calibrated (lost_reason field completion, lead scoring threshold review, UTM coverage audit, sequence reply rate review, event schema drift check).
- **Change plan summary**: consolidated list of every proposed CRM or tool change, formatted as: object type, field name, change type (add/edit/remove), current value, proposed value, rationale.
