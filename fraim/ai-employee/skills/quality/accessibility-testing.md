# FRAIM Skill: accessibility-testing

## Skill Input
- `targetSurfaces`: URLs, routes, or rendered components to test.
- `requiredJourneys`: Primary keyboard and pointer journeys to exercise.
- `requiredStates`: UI states to inspect, such as loading, empty, error, success, disabled, hover, active, and populated.
- `themes`: Theme modes to validate. Include light and dark when the application supports both.
- `breakpoints`: Viewports or devices to validate, especially mobile widths where focus, labels, and contrast often regress.
- `targetCompliance`: Optional WCAG target. Default to WCAG 2.1 AA for web UI unless the caller provides a stricter standard.

## Skill Output
- `accessibilityFindings`: Evidence-backed pass/fail findings with severity, affected surface, user impact, WCAG reference where applicable, and exact repro steps.
- `contrastMatrix`: Text, control, icon, and focus-state contrast checks across relevant themes and states.
- `keyboardAndAssistiveTechFindings`: Keyboard, focus, accessible-name, form-label, live-region, dialog, and screen-reader-risk findings.
- `remediationQueue`: Ordered fixes for all Critical/High issues, with verification steps.
