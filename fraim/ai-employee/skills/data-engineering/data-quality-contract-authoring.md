# FRAIM Skill: data-quality-contract-authoring

## Skill Input
- Table or dataset specification: schema definition with column names, types, and business descriptions.
- Upstream source information: which pipeline stage or system produces this data.
- Downstream consumer list: which dashboards, models, or APIs depend on this data.
- Historical quality incidents (optional): known data quality issues, past null spikes, type mismatches, or duplicate events.
- SLA requirements: freshness requirements from downstream consumers.

## Skill Output
- **Schema Contract**: Formal definition of the table's expected schema — column names, types, nullability, and uniqueness constraints.
- **Quality Rule Set**: A list of named quality rules in the format: Rule ID, Rule Name, Column(s), Rule Logic, Severity (HIGH / MEDIUM / LOW), Action on Failure.
- **Freshness SLA**: The maximum acceptable age of the data at the time a consumer queries it. Expressed as a duration (e.g., "data must be ≤ 2 hours old at time of query").
- **Alerting Configuration**: For each HIGH-severity rule violation, the alerting destination (PagerDuty, Slack, email) and escalation path.
- **Contract Changelog**: Versioned log of schema and rule changes with the change description, author, and date.
