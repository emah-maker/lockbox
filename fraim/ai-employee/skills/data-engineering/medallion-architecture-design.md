# FRAIM Skill: medallion-architecture-design

## Skill Input
- Source system inventory: list of data sources with system type (OLTP DB, SaaS API, file export, streaming), schema or sample, and update frequency.
- PII classification: which sources contain personally identifiable information and what field types (email, name, SSN, phone, location).
- Downstream consumers: the analytics use cases, BI tools, and ML models that will consume the data.
- SLA requirements: acceptable data freshness per consumer (e.g., "fraud detection requires < 5 min latency; monthly reporting can be T+1 day").
- Warehouse platform: Snowflake, BigQuery, Redshift, Databricks, or DuckDB.

## Skill Output
- **Bronze Layer Design**: Raw ingestion schema per source. Storage format (Parquet, Delta, Iceberg). PII field inventory with masking approach per field.
- **Silver Layer Design**: Cleansed, deduplicated, and conformed schema. PII masking applied. Business entity definitions (customer, order, session). Schema contract per table.
- **Gold Layer Design**: Analytics-ready aggregates and dimensional models. No PII in Gold. Named consumer mappings (which Gold table serves which use case).
- **Pipeline Orchestration Diagram**: DAG structure — source → Bronze → Silver → Gold — with transformation steps, dependencies, and SLA checkpoints.
- **PII Handling Matrix**: Per-source, per-field: data classification (PII/non-PII), masking technique (hash, tokenize, nullify, pseudonymize), and the layer at which masking is applied.
