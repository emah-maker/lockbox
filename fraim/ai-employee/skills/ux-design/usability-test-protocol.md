# FRAIM Skill: usability-test-protocol

## Skill Input
- Test objective: the specific question the test is designed to answer (e.g., "Can users complete the onboarding flow without assistance?" or "Do users understand the pricing model?").
- Prototype or live product: the artifact to be tested (Figma prototype, staging environment, or production).
- Task list: the 3–5 specific tasks participants will attempt during the session.
- Participant criteria: the target user profile (role, experience level, familiarity with the product).
- Number of participants: target 5 for qualitative insight; 8–12 for quantitative task completion rates.

## Skill Output
- **Test Protocol Document**: Session structure, facilitator script, task descriptions, and probe questions.
- **Observation Framework**: A structured note-taking template capturing: task completion (success/partial/fail), time on task, error count, and observed behaviors and verbatim quotes.
- **Severity Scoring Matrix**: For each finding, a severity score = frequency (how many participants encountered it) × impact (how much it impaired task completion). Scale: 1–5 for each dimension.
- **Findings Report**: Findings grouped by severity, with: description, evidence (observation + quote), severity score, and recommended fix.
