# FRAIM Job: support-playbook-evaluation

## Intent
Back-test approved support SOP playbooks against historical or golden support tickets, so an enterprise can see whether tickets would have been routed correctly before enabling live support automation.

## Outcome
- **Reviewable deliverable**: a .docx review copy generated from the final artifact via the author-docx skill at submission; this is the outcome delivered for review, with the .md below as the canonical agent-side record
- Final artifact: A markdown report at `docs/support/playbook-evaluations/support-playbook-evaluation-{YYYY-MM-DD}.md` with dataset summary, playbooks tested, decision prompt/version, accuracy, confusion matrix, failure examples, automation eligibility, human-review rate, and recommended playbook improvements
- **Spreadsheet deliverable**: A CSV/XLSX-ready row-level results file at `docs/support/playbook-evaluations/support-playbook-evaluation-{YYYY-MM-DD}.csv` with ticket id, expected decision, actual decision, pass/fail, confidence, failure reason, and recommendation columns
- Dry-run playbook decision results for every evaluated ticket
- Evidence that prohibited or ambiguous tickets route to human review
- Clear recommendation on whether the playbook is ready for live HITL use, autonomous use, or further tuning

## Steps
1. Phase 1: `evaluation-scoping`
2. Phase 2: `dataset-preparation`
3. Phase 3: `decision-backtest`
4. Phase 4: `analyze-results`
5. Phase 5: `recommend-improvements`
6. Phase 6: `produce-report`
7. Phase 7: `submit`
