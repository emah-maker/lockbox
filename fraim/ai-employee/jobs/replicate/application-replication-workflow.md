# FRAIM Job: application-replication-workflow

## Intent
To systematically discover, analyze, and document an existing web application for replication, then convert the analysis into actionable GitHub issues for implementation through standard FRAIM product-building workflows.

## Outcome
- **Comprehensive Analysis**: Complete `REPLICATION_ANALYSIS.md` report and `INDEX.md` in `docs/replicate/`.
- **Structured GitHub Issues**: One issue per feature/use case, properly labeled, prioritized, and linked.
- **Implementation Roadmap**: A phased plan for building the replicated application.
- **Developer Guide**: Documentation on how to pick up and work on these issues.
- **Final artifact set**: `REPLICATION_ANALYSIS.md`, `INDEX.md`, `IMPLEMENTATION_ROADMAP.md`, `GITHUB_ISSUES.md`, `DEVELOPER_GUIDE.md`, plus the screenshots directory. The per-phase JSON analyses and report files are working state and are removed once the master report consolidates them.

## Steps
1. Phase 1: `initialize-output-structure`
2. Phase 2: `initial-site-scraping`
3. Phase 3: `interactive-browser-analysis`
4. Phase 4: `screenshot-organization`
5. Phase 5: `technology-stack-analysis`
6. Phase 6: `use-case-extraction`
7. Phase 7: `master-report-generation`
8. Phase 8: `prepare-issue-generation`
9. Phase 9: `categorize-and-prioritize`
10. Phase 10: `generate-github-issues`
11. Phase 11: `link-and-organize-issues`
12. Phase 12: `document-issues`
13. Phase 13: `replication-submission`
14. Phase 14: `address-feedback`
15. Phase 15: `retrospective`
