# FRAIM Job: compliance-continuous-monitoring

## Intent
Between `compliance-review` runs, detect drift — controls whose status has changed since the last bundle (Pass → Fail, evidence expired, policy stale) — and file `compliance:drift` issues before the next audit cycle.

## Outcome
- **Reviewable deliverable**: A .docx document at docs/compliance/compliance-continuous-monitoring-{YYYY-MM-DD}.docx containing drift analysis summary with control status changes, evidence expiration details, and severity-classified findings.
- **Filed drift issues**: One per drifted control (deduplicated).
- **Idempotence**: A second run with no intervening changes files no new issues.

## Steps
1. Phase 1: `baseline-load`
2. Phase 2: `current-state-scan`
3. Phase 3: `drift-analysis`
4. Phase 4: `drift-report-and-file`
5. Phase 5: `address-feedback`
6. Phase 6: `retrospective`
