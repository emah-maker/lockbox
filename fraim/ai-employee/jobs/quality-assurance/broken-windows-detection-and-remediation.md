# FRAIM Job: broken-windows-detection-and-remediation

## Intent
Identify and eliminate "broken windows" in codebases by detecting pattern deviations that cause AI agents to learn bad patterns and degrade code quality over time. Focus on finding "needles in the haystack" - files that deviate from established codebase patterns.

Use this job when AI agents start producing inconsistent code, after significant codebase changes, or when pattern inconsistencies are reported during code reviews. Targets pattern consistency issues that confuse AI agents rather than functional bugs.

## Outcome
- **Reviewable deliverable**: A .docx document at docs/quality-assurance/broken-windows-report-{YYYY-MM-DD}.docx with Pattern Consistency, Broken Windows findings, and Actionable Remediation Plan sections.
- **Pattern Consistency**: Identified dominant and minority patterns in the codebase.
- **Actionable Remediation**: Specific file paths for broken windows and a prioritized remediation plan.

## Steps
1. Phase 1: `codebase-pattern-discovery`
2. Phase 2: `broken-window-detection`
3. Phase 3: `remediation-planning`
4. Phase 4: `broken-windows-report-generation`
5. Phase 5: `broken-windows-submission`
6. Phase 6: `address-feedback`
7. Phase 7: `retrospective`
