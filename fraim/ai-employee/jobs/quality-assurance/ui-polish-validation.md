# FRAIM Job: ui-polish-validation

## Intent
Catch UI fit-and-finish defects that coding agents frequently miss: overlap, clipping, overflow, wrong font, wrong colors, spacing drift, and interaction polish issues.

## Outcome
- Final artifact: The validation report at `docs/evidence/{issue_number}-ui-polish-validation.md` with quality contract, evidence matrix across breakpoints/states, defect inventory with severity/reproducibility, and final signoff (PASS/PARTIAL/FAIL).
- UI quality contract is explicit and approved.
- Deterministic browser evidence is captured for all required breakpoints and states.
- Screenshot and browser artifacts are stored under `docs/evidence/ui-polish/{issue_number}/`, within the screenshot budget.
- Defects are filed with reproducible evidence.
- Fixes are verified with regression checks before signoff.
- A .pptx export at `docs/quality-assurance/ui-polish-validation-{YYYY-MM-DD}.pptx` is generated only when the user asks for a presentation; the .md report is the canonical record.

## Steps
1. Phase 1: `intake-and-quality-contract`
2. Phase 2: `environment-and-baseline-setup`
3. Phase 3: `static-preflight-checks`
4. Phase 4: `playwright-user-journey-smoke`
5. Phase 5: `responsive-layout-audit`
6. Phase 6: `typography-and-color-audit`
7. Phase 7: `overlap-overflow-and-clipping-audit`
8. Phase 8: `interaction-and-accessibility-audit`
9. Phase 9: `console-and-network-health-audit`
10. Phase 10: `evidence-and-defect-triage`
11. Phase 11: `fix-and-regression-loop`
12. Phase 12: `final-signoff`
