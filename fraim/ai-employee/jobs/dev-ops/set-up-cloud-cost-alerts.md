# FRAIM Job: set-up-cloud-cost-alerts

## Intent
Get warned before cloud credits run out so the user is never surprised by a card charge. Two-tier guardrail: a zero-spend tripwire that fires the instant any paid usage starts after credits exhaust, and a tiered cost budget for trajectory visibility once the user is intentionally spending. Distinct from `cloud-cost-optimization` — that job reduces existing spend; this one prevents surprise spend.

## Outcome
- Final artifact: `docs/cloud-cost-alerts/<cloud>-{DATE}.md` capturing what was configured and how to test/edit.
- **Zero-spend tripwire** active: alert email goes out the instant actual usage exceeds the sub-cent threshold (i.e., the moment credits stop covering it).
- **Tiered budget** active (optional): alerts at 50% / 80% / 100% of a user-chosen monthly limit.
- **Confirmed delivery**: a test email has actually arrived in the user's inbox.

## Steps
1. Phase 1: `platform-selection`
2. Phase 2: `verify-authentication`
3. Phase 3: `configure-zero-spend-tripwire`
4. Phase 4: `configure-tiered-budget`
5. Phase 5: `verify-alert-delivery`
6. Phase 6: `retrospective`
