# FRAIM Job: security-review

## Intent
Perform a standalone security review against an explicit review scope - repository, directory, branch, PR, or diff - using OWASP Top 10 (Web, API, LLM), privacy / PII, secrets-in-code, and capability-authoring checks. The run can auto-fix narrowly safe issues, file GitHub issues for anything non-trivial, or record an accepted or deferred risk with justification.

## Outcome
- **Reviewable deliverable**: A .pptx presentation at docs/security/security-review-{target}-{YYYY-MM-DD}.pptx containing OWASP coverage matrix, threat surface assessment, findings severity dashboard, remediation queue, verification evidence, and compliance control mapping
- A common FRAIM security review report with scope, threat surfaces, coverage matrix, findings, remediation queue, verification evidence, and compliance mapping
- **Auto-fix commits**: zero or more commits on the current branch with message prefix `security(<OWASP_CODE>): ...`, capped at 10 per run
- **GitHub issues**: non-auto-fixable findings filed with labels `security`, `severity:<level>`, and at least one `owasp:*` label
- **Evidence feed**: the report is consumed by `generate-audit-evidence` so SOC2 / ISO 27001 audits have pre-built evidence of the review

## Steps
1. Phase 1: `threat-surface-detection`
2. Phase 2: `security-scan`
3. Phase 3: `fix-or-file`
4. Phase 4: `security-report`
5. Phase 5: `address-feedback`
6. Phase 6: `retrospective`
