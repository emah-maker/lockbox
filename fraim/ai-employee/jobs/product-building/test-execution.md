# FRAIM Job: test-execution

## Intent
Systematically design, implement, and verify tests for a specific issue, ensuring that the issue is reproducible and that the fix will be verifiable. This job focuses purely on the *testing* aspect, often run before implementation to establish a TDD baseline.

## Outcome
- **Failing Test(s)**: A new or updated test suite that reproduces the issue (for bugs) or defines the contract (for features).
- **Test Plan**: Documented strategy for coverage (Happy Path, Edge Cases, Error States).

## Steps
1. Phase 1: `test-planning`
2. Phase 2: `test-implementation`
3. Phase 3: `test-verification`
4. Phase 4: `test-submission`
5. Phase 5: `address-feedback`
6. Phase 6: `retrospective`
