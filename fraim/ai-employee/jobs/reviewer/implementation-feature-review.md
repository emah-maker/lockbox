# FRAIM Job: implementation-feature-review

## Intent
To systematically verify that the implementation solves the customer problem and delivers the user experience described in the feature spec, ensuring **completeness**, **correctness**, and **quality** of functional requirements and user value.

## Outcome
- Final artifact: A single review report at `docs/evidence/{issue}-feature-review.md` with `decision` and `iteration` frontmatter and round-by-round findings.
- **Approved Implementation**: Confirmation that the feature meets spec and user value.
- **Actionable Feedback**: Clear guidance for implementation agents if changes are needed.

## Steps
1. Phase 1: `load-feature-spec-context`
2. Phase 2: `feature-spec-completeness-check`
3. Phase 3: `customer-problem-verification`
4. Phase 4: `authentication-setup-for-e2e`
5. Phase 5: `user-experience-validation`
6. Phase 6: `ui-mock-compliance-check`
7. Phase 7: `edge-negative-error-validation`
8. Phase 8: `functional-completeness-check`
9. Phase 9: `feature-review-decision-and-feedback-creation`
10. Phase 10: `feature-review-submission`
11. Phase 11: `address-feedback`
12. Phase 12: `retrospective`
