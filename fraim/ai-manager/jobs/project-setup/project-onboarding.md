# FRAIM Job: project-onboarding

## Intent
Onboard a project into a trustworthy FRAIM-ready state by reusing what FRAIM can already detect, asking only for the highest-value missing details, and writing durable project context without forcing an exhaustive schema walkthrough up front.

## Outcome
- `fraim/config.json` contains the approved project metadata and validation settings needed for future FRAIM work.
- `fraim/personalized-employee/context/project_context.md` captures durable project facts: what this project is, how it is structured, and what future agents should understand before working.
- `fraim/personalized-employee/rules/project_rules.md` captures durable project-wide operating rules for future agents.
- The user understands what FRAIM confirmed automatically, what still needs input, what can be added later, and which next FRAIM reviews or scaffolding jobs would make this specific project stronger.

## Steps
1. Phase 0: `sync`
2. Phase 1: `scope`
3. Phase 2: `write`
4. Phase 3: `validate`
5. Phase 4: `submit`
6. Phase 5: `address-feedback`
7. Phase 6: `retrospective`
