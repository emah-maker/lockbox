# FRAIM Job: organization-onboarding

## Intent
Onboard your organization once so every AI employee works from shared org context and always-on guardrails, instead of re-deriving them from scratch on every project.

## Outcome
- `org_context.md` captures the organization identity, domain, and key tools; `org_rules.md` captures the always-on organizational guardrails.
- Both artifacts live in the organization's shared backend so every member, machine, and project reads the same version: the FRAIM-managed organization by default, or a git repository the team controls. On a machine with no shared backend configured, they live machine-level at `~/.fraim/personalized-employee/`.
- The manager has reviewed both artifacts through the normal submit/feedback flow and knows these Layer-1 artifacts are inherited by every project onboarding.

## Steps
1. Phase 0: `sync`
2. Phase 1: `scope`
3. Phase 2: `derive`
4. Phase 3: `synthesize`
5. Phase 4: `validate`
6. Phase 5: `submit`
7. Phase 6: `address-feedback`
8. Phase 7: `retrospective`
